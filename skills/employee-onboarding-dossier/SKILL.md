# 祥能集团人员入职资料生成规范 (Employee Onboarding Dossier)

## 概览

本技能用于将求职者提交的散乱入职材料（PDF、JPG、PNG、企业微信截图等）一键整理为符合祥能集团人力资源部标准的 `《{姓名}-入职资料.docx》`，并在发现必交项缺失时自动给出**缺失材料提醒清单**。

## 核心业务口径与排版标准（基于已确认规范）

1. **封面规范（100% 沿用原版模板 `templates/base_template.docx`）**：
   - 右上角保留祥能集团 Logo（`image1.png`）。
   - 主标题：`祥能集团人员入职资料`（居中，26pt）。
   - 四行下划线信息（18pt）：
     - `姓名：`（前后空格居中填入选人姓名）
     - `应聘岗位：`（填入用户指定岗位，注意可能与简历文件名上的历史投递岗位不同，以用户口头/明确指令为准）
     - `所属部门：`（填入用户指定的部门或分子公司）
     - `资料：`默认固定为 `应聘登记及面试记录表、简历、相关资质证书      `
   - 落款日期（右对齐，15pt）：`人力资源部制：  _{年}_年_{月}_月`（默认取当前年月）。

2. **标准章节顺序与动态顺延规则**：
   - 使用中文一级自动编号（`一、 二、 三、...`，加粗，左对齐）。
   - **有什么材料就排什么章节，暂时未交的材料允许空缺跳过，编号自动顺延**，先生成汇报版 Word 文档。
   - **标准推荐章节顺序**：
     1. `《应聘人员登记表》`（或见习生的 `成都市就业见习申请表`）
     2. `面试评价` / `面试评价表`（如有）
     3. `背调结果`（**仅专员、主管、经理级及以上岗位需要背调**；普通助理/见习生/一线基层岗默认不要求背调）
     4. `个人简历`（PDF 拆页或长图）
     5. `性格测试结果`（**特殊版式**：内嵌居中截图 + 页面下方两个带黑框的白色悬浮文本框）
     6. `个人征信报告`（多页时第 1 页带编号 `个人征信报告`，后续页标题为 `个人征信报告（第2页）`、`个人征信报告（第3页）` 且**不带中文序号**）
     7. `无犯罪记录证明`
     8. `毕业证书`（若有学位证、学籍在线验证报告、相关职称/退伍/职业资格证，可紧随其后或将毕业证与学位证上下同页排布）
     9. `证件照`（高约 `155pt`，与下方的 `身份证` 同处一页）
     10. `身份证`（正反面两张图上下排布，宽约 `235pt`、高约 `145pt`，与上方的 `证件照` 共用一页）
     11. `体检报告`（如有，排在最后）

3. **性格测试结果页“两段式悬浮文本框”生成规范**：
   - 识别求职者性格测试截图中的 MBTI 类型（如 `ESTJ`、`ENFJ`、`ENTJ`、`INTJ` 等），结合**本次实际应聘岗位**自动撰写两段式分析（宋体小四 `12pt`，首行缩进 2 字符）：
     - **上方文本框（`fit`，约 90~130 字）**：`{MBTI} 的{核心优势倾向}与{应聘岗位}岗位中的{核心工作场景}相契合。{应聘岗位}需要负责{列举5~6项该岗位具体日常职责}等工作，其中{点出3项最匹配的事务}，可为其发挥{3项性格长处}提供空间。`
     - **下方文本框（`trait`，约 80~115 字）**：`{MBTI} 类型{描述性格特质、行事风格与偏好}。在工作中可注意{给出兼顾平衡的温和建议}，避免因{该性格极端倾向}而{潜在副作用}。`
   - **严禁事项**：悬浮文本框 `<v:shape>` 内部的 `<v:imagedata>` 绝对不能带有 `r:id` 属性，否则 Word 会把性格测试截图当成文本框背景图拉扁填充！`scripts/build_dossier.py` 已内置防呆清理逻辑。

4. **必交项核验与缺失提醒机制**：
   - **常规必交全套清单**：① 应聘人员登记表（或见习申请表）、② 面试评价表、③ 背调结果（仅专员/主管级及以上）、④ 个人简历、⑤ 性格测试结果、⑥ 个人征信报告、⑦ 无犯罪记录证明、⑧ 毕业证书（及学位证/学籍证明）、⑨ 证件照、⑩ 身份证（正反两面）、⑪ 体检报告。
   - 当发现求职者文件夹中缺少上述应交材料时，**不要中断生成**，先用已有材料生成完整的 `{姓名}-入职资料.docx`，然后在聊天回复中清晰列出**《缺失/待补交材料提醒清单》**供 HR 催交。

## 标准执行工作流 (Workflow)

### 步骤 1：盘点与识别原始素材
1. 扫描用户提供的文件夹，列出所有 PDF 和图片文件。
2. 若存在 `.pdf` 文件，调用内置工具将 PDF 渲染为高清 PNG：
   ```bash
   python3 /Users/wangmini/.gemini/config/skills/employee-onboarding-dossier/scripts/build_dossier.py render-pdf \
     --pdf "/path/to/file.pdf" \
     --outdir "/tmp/dossier_pdf_pages"
   ```
3. 使用 `read_file` 快速查看各图片（或渲染出的页面），确认：
   - 每张图对应的模块类别（登记表、面试评价、简历、MBTI性格测试截图及具体字母类型、征信报告第几页、无犯罪证明、毕业证/学位证、证件照、身份证正面/反面、体检报告）。
   - 检查是否有横置/倒置的图片（如旋转了 90° 的毕业证或简历），记录需要顺时针旋转的角度（`rotate`: `90` / `180` / `270`）。

### 步骤 2：编写 JSON 清单 (`manifest-{姓名}.json`)
在目标目录或临时目录生成结构化的 `manifest-{姓名}.json`：

```json
{
  "name": "毛宇菲",
  "position": "行政助理",
  "department": "公共事务部",
  "year": "2026",
  "month": "10",
  "items": [
    {
      "caption": "《应聘人员登记表》",
      "images": [{ "path": "/abs/path/to/form.png" }]
    },
    {
      "caption": "面试评价",
      "images": [{ "path": "/abs/path/to/eval.png" }]
    },
    {
      "caption": "个人简历",
      "images": [{ "path": "/abs/path/to/resume.pdf" }]
    },
    {
      "caption": "性格测试结果",
      "personality": true,
      "images": [{ "path": "/abs/path/to/mbti.png" }],
      "p": {
        "fit": "ESTJ 的执行力与流程意识与行政助理岗位中的日常事务统筹相契合……",
        "trait": "ESTJ 类型务实、重秩序，倾向于按既定规则和流程推进事务……"
      }
    },
    {
      "caption": "个人征信报告",
      "images": [{ "path": "/abs/path/to/credit.pdf" }]
    },
    {
      "caption": "无犯罪记录证明",
      "images": [{ "path": "/abs/path/to/nocriminal.jpg" }]
    },
    {
      "caption": "毕业证书",
      "images": [
        { "path": "/abs/path/to/diploma.png" },
        { "path": "/abs/path/to/degree.png" }
      ]
    },
    {
      "caption": "证件照",
      "photo": true,
      "images": [{ "path": "/abs/path/to/photo.jpg" }]
    },
    {
      "caption": "身份证",
      "id_card": true,
      "images": [
        { "path": "/abs/path/to/id_front.jpg" },
        { "path": "/abs/path/to/id_back.jpg" }
      ]
    }
  ]
}
```
> **提示**：`images` 数组中的 `path` 可以直接填 `.pdf` 路径，`build_dossier.py` 会自动调用原生 PDFKit 拆页渲染，且当 `caption` 为 `"个人征信报告"` 时会自动为第 2 页起添加 `"个人征信报告（第2页）"` 副标题。

### 步骤 3：运行脚本生成 Word 文档
调用 `build_dossier.py` 生成最终 `.docx` 文件（默认保存在求职者原始文件夹内）：

```bash
python3 /Users/wangmini/.gemini/config/skills/employee-onboarding-dossier/scripts/build_dossier.py create \
  --manifest "/path/to/manifest-姓名.json" \
  --output "/path/to/姓名-入职资料.docx"
```

### 步骤 4：交付文档与缺失材料核对清单
向用户返回生成的 Word 文件链接、已收录章节列表、自动生成的 MBTI 岗位契合度分析预览，以及**缺失材料提醒清单**（区分“常规必交缺失”与“职级条件项如背调”）。

## 常见错误与防范 (Common Mistakes)

- **避免文本框图片污染**：切勿给性格测试悬浮文本框 `<v:shape type="#_x0000_t202">` 内的 `<v:imagedata>` 赋予 `r:id`，只有内嵌截图 `<v:shape type="#_x0000_t75">` 才能绑定图片 `r:id`。
- **避免身份证正反面占满整页**：身份证正反面应使用 `id_card` 模式（宽约 `235pt`、高约 `145pt`），并与 `证件照`（高约 `155pt`）紧凑排布在同一页，不要把身份证放大到 `523pt` 整页宽。
- **注意应聘岗位以用户指令为准**：求职者简历文件名可能带有旧岗位名称（如 `毛宇菲（新媒体助理见习生）.pdf`），但用户实际录用岗位可能是 `公共事务部-行政助理`，封面及 MBTI 契合度分析必须严格使用用户指定的最新部门与岗位。
