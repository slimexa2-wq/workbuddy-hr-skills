# 招聘全漏斗分析与去重归因规范

适用于蓝领/制造业（普工、技工、操作工、质检、叉车等）及白领岗位的多渠道招聘台账清洗、去重与四段转化漏斗核算。

## 1. 候选人唯一标识与 30 天滑窗去重铁律
1. **唯一主键优先级**：
   - 第一优先：`手机号（清洗掉空格、短横线、+86 后的 11 位纯数字）`
   - 第二优先：`姓名 + 身份证号后 4 位`（无手机号时兜底）
   - 严禁仅按“姓名”去重（蓝领招聘同名率极高）。
2. **30 天滑窗最早锚点去重（First-Touch Attribution）**：
   - 同一候选人在 **30 个自然日内**被多个渠道（如劳务中介 A、抖音直播间、智联招聘）重复提报，或多次投递同一项目时：**归因于最早登记的那条记录（First-Touch）**，后续重复记录标记为 `重复提报（不计入分母，更不重复计入返费/提成）`。
   - 超过 30 天且前次未入职/已离职满规定冷却期的，视为新一轮应聘周期。

## 2. 标准四段转化漏斗与防 `>100%` 断层铁律
标准漏斗四阶段：
$$\text{有效线索/简历 (Lead)} \longrightarrow \text{到面/初试通过 (Interviewed)} \longrightarrow \text{Offer/体检通过 (Offered)} \longrightarrow \text{实际报到入职 (Onboarded)} \longrightarrow \text{满月/过保留存 (Retained)}$$

### 高频踩坑：为什么某渠道“入职 / Offer”或“Offer / 到面”转化率会 `> 100%`？
- **根因**：蓝领现场直聘、厂门口直招或劳务批量送人场景下，HR 常漏填中间环节（直接登记“已入职”，但“Offer 时间”或“面试状态”为空），若直接按非空字段各自 `COUNT()`，会导致下游人数大于上游人数（转化率 `>100%`）。
- **强制修正规则（上游推定补齐 / Imputed Funnel）**：
  - 凡是存在真实下游时间戳或状态的记录（例如 `已入职 = 是`），在计算漏斗分子分母时，**必须强制向上游推定补齐**（即：`已入职` 必然计入 `已发 Offer/体检通过`，也必然计入 `已到面` 和 `有效线索`），同时在数据质量备注中单独列出“漏填中间状态 X 人”。
  - 任何环节转化率一旦出现 `> 100%`，严禁直接出表，必须先执行上游推定补齐并核查是否存在跨期错位（如上月发 Offer、本月入职）。

## 3. 跨期对账口径（Cohort vs Period）
- **同批追踪口径（Cohort Funnel，推荐用于渠道质量评估）**：以“线索登记周/月”锁定人群，追踪这批人最终有多少到面、入职、留存。
- **当期发生口径（Period Snapshot，推荐用于日报/周报工作量统计）**：统计当周实际发生的面试数、当周实际报到人数，汇报时必须注明“含往期线索当期入职 X 人”，避免将两个口径混算成同一个百分比。
