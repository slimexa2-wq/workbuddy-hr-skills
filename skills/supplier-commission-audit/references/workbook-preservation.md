# 原表追加审核列的保留与复检

适用于用户要求“结果加在原表新增列，原表格式不动”的交付。先使用当前可用的表格能力读写；工具不可用时说明实际限制，不照搬其他操作系统的COM方案。

## 先选择保留方式

- 对原文件建副本，写入前记录目标文件、所有明细表、原始已用列范围及新增列起点；不要假定只有名为“明细”的一张表。
- 能可靠保留全部原结构的原生编辑器可直接在副本追加列，批量写入新增值和颜色，然后核对原区域。
- `.xlsx`经过通用读写库整簿重存可能丢失扩展、外链、图片或改变默认行列属性。若存在这类风险，可在满足当前表格工具要求的前提下先生成新增单元格片段，再合入原OOXML包，只修改必须修改的工作表和样式部分。
- `.xls`不是OOXML ZIP，不能套用XML合入。选支持该格式的工具；若必须转换，保留原件、标明转换副本并验证，不能暗改后缀当作转换。

## OOXML最小合入的关键点

这是一种经过本次交付验证的实现路线，不要求每次都重新实现。实际使用前验证对当前文件特性的支持。

1. 从`workbook.xml`及关系文件解析工作表名与真实XML路径，不猜`sheet1.xml`对应业务表。
2. 保持原ZIP包条目及关系，原单元格、公式、原共享字符串和原样式索引不变。只在目标行加入新列单元格，必要时扩展dimension与新增列宽；不修改原行属性、隐藏状态、合并区域或原列配置。
3. 新增样式附加到原样式表末尾，正确映射片段内的字体、填充、边框、数值格式和cellXfs引用；不重排原样式。只靠样式数量增加不证明原样式未变。
4. 新文本可转成inlineStr，避免覆写原共享字符串。保留XML命名空间及标记兼容声明；不触发外链刷新或原公式重算。
5. 用`zipfile`搬运条目时，传给`writestr`的`ZipInfo`应先复制；复用原对象会改变其header_offset，导致随后读取原包时出现BadZipFile。不要复制一份已损坏的内存索引继续验证。
6. 长依据写在新列内，首句给出结论，保留完整单元格值。不要通过自动适配行高破坏原表；长说明的可见高度受原行高限制，文字汇报补充重点。
7. **幽灵空列清理与内置工具复用**：直接复用技能包内置的 `scripts/ooxml_append.py`。部分原表（如《正能外包》）在新增列起点之后存在直达 `16,382` 列的空格式单元格（`<c>` 无值）或超宽 `<col min=".." max="16384">` 定义；合入新列时应清理所有行中 `col_idx >= start_col_idx` 的残留空单元格，并将跨越 `start_col_idx` 的原 `<col>` 的 `max` 截断至 `start_col_idx - 1`，再追加6列宽度定义。注意解析 `workbook.xml.rels` 时先对 `Target` 执行 `.lstrip("/")` 再判断 `xl/` 前缀，兼容原生 Excel 与 `openpyxl` 转换副本。

## 有意义的完成校验

- 原文件哈希未变；交付文件是独立副本。
- 原区域逐格的值、公式、样式及显示设置保持一致，包括默认行高、列宽、隐藏、合并、其他工作表和外链等。采用ZIP最小修改时，未涉及的包条目内容应一致；样式原有定义应保持不变。
- 新增六列在每个目标明细表都存在；读回的身份、行号、金额、结论和证据位置与审核结果一致。不要按排序后的结果列表直接覆盖原行。
- 原先通过项没有被重新改判；零元仍跳过；正向审核金额不增加；部分待核可分拆，金额分类没有交叉重复。
- 对包含多个明细表、隐藏列、固定行高、跨表公式或外链的代表文件检查展示。结构校验不能冒充已做视觉检查，不能宣称固定小行高能完整显示所有长说明。
- 逐人及供应商合计与原精度对账。分别列真实多付、供应商归属调整和待核；发现不能平衡时定位到行，不用手改总数凑平。

未经上述核对，不宣称“原格式完全不变”或“审核已全部通过”。
